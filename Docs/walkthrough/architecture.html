At a glance

One FastAPI application does the synchronous work. Four background processes do the rest. Everything that matters is written to PostgreSQL first; the graph, the event topic and the vector index are rebuildable copies.

One governed question, end to end

Ask a question in plain English and the platform walks a fixed ladder. Each rung names its state, so an audit record can say exactly how far a request got. Policy and prompt-risk screening happen before retrieval, and the query gateway sits between every model output and the source.

StateWho actsWhat has to be true to continue
AUTHORIZEDAPIThe caller has a verified identity and an organization.
SCREENEDPrompt-risk screenThe question passes. A denial stops here, before any retrieval.
RESOLVEDPolicy, retrieval, graphConcepts, metrics and join paths resolve to objects this caller may see.
PLANNEDRetrievalContext is ranked and policy-filtered; the model sees metadata only.
GENERATEDModel gatewayA schema-validated SQL proposal comes back from an approved route. It is a proposal, never a command.
VALIDATEDQuery gatewayThe SQL is parsed to an AST and every referenced object is checked against policy.
COSTEDQuery gatewayEXPLAIN on the source returns a plan and an estimated cost.
EXECUTEDQuery gatewayRead-only and bounded; results are masked by classification and carry lineage.
EXPLAINEDModel gateway, auditThe explanation, evidence, versions and decision lineage are recorded.

When an approved tool already answers the question, the platform reuses it instead of generating SQL. That is the preferred path.

Nine invariants, and the test that holds each one

These are the rules the design refuses to trade away. Each has an enforcement point and a named test, so a change that breaks one fails a build rather than a review.

Code layout

The design describes 21 bounded contexts. Six exist as real packages under src/atlas/modules; the rest of the behaviour still lives in the flat src/aida package. The map below is generated from the source tree, so it cannot drift.

Thirteen import-linter contracts guard the boundaries, including the one that lets only the query gateway reach source SQL and the newest, which keeps GraphQL from reaching an execution path. The map itself flags 15 imports from domain modules into routers, so the layers are described, not yet mechanically enforced.

Designed vs built

The documents keep the design intent and mark where the code has not caught up. These are the differences a reviewer is most likely to find.
